# personalwebsite Wiki 总览

这是一个面向个人作品集的无框架静态站点，使用 Node.js 原生模块把站点配置、共享 HTML 外壳和页面正文模板生成可提交的根目录 HTML。页面内容聚焦 AI 产品经理、电商运营、Workflow、商品视觉、数据分析与 RPA 实践，仓库本身负责静态展示和发布，不承载这些案例背后的模型或业务后端。

仓库将源文件与产物分开管理：`site.config.json` 维护品牌、页面清单和公开联系方式，`templates/` 保存共享布局与各页正文，`build.mjs` 负责校验、渲染、漂移检查和 `dist/` 发布构建。浏览器端的 `site.js` 只提供日期、任职时长和复制邮箱等渐进增强，`pages.css` 负责共享视觉系统与响应式布局。

发布侧同时保留两种兼容边界。根目录生成 HTML 可配合 `_config.yml` 的 Jekyll 根目录设置，GitHub Actions 则在 Node.js 22 环境中执行部署构建并上传 `dist/` 到 GitHub Pages。维护时应先修改模板、配置或素材，再运行 `npm run build`，用 `npm run check` 检查生成 HTML 与源文件是否一致，最后按需要生成部署目录。

## 章节导航

- 开发与构建 —— 解释无框架静态站的源文件边界、Node.js 要求、构建命令和渲染输出。
- 配置与页面 —— 说明页面配置模型、八个入口的内容职责、共享布局与媒体素材。
- 交互与样式 —— 记录 `site.js` 的渐进增强、无障碍反馈、CSS 设计系统和响应式断点。
- 部署与维护 —— 说明 GitHub Actions 的 `dist/` 发布、Jekyll 兼容配置和日常一致性校验。

## 如何使用本 Wiki

新手可以先阅读“开发与构建”，了解模板、配置、生成 HTML 和 `dist/` 的关系；然后阅读“配置与页面”，建立页面导航、案例内容和素材路径的整体认识；最后阅读“交互与样式”与“部署与维护”，补齐浏览器行为、响应式设计和发布操作。按这个顺序阅读，可以先掌握静态文件如何产生，再理解访客看到什么以及页面如何上线。

贡献者可以从准备修改的边界进入：改页面文案或截图时查看“配置与页面”，改复制邮箱、日期或可访问反馈时查看“交互与样式”，改工作流或发布路径时查看“部署与维护”。每次修改完成后按“开发与构建”中的命令顺序重建并检查，确认生成 HTML 和部署目录符合预期，再提交源文件与需要提交的根目录产物。

## 术语表

- 静态站（Static site）：由预生成 HTML、CSS、JavaScript 和媒体文件组成，浏览器无需等待应用服务器渲染页面。
- 共享布局（Shared layout）：`templates/layout.html` 提供所有页面共用的头部、导航、元数据、正文插槽和页脚。
- 页面正文模板（Page template）：`templates/pages/` 下与页面文件同名的 HTML 片段，保存各页具体文案和区块。
- 站点配置（SiteConfig）：`site.config.json` 中的站点级字段与 `pages` 页面清单，作为生成器的结构化输入。
- 页面配置（PageConfig）：`pages` 数组中的一项，描述文件名、导航标签、标题、摘要和预留图标字段。
- 构建器（Build script）：`build.mjs`，负责校验配置、展开占位符、生成 HTML、检查漂移和创建 `dist/`。
- 占位符（Placeholder）：布局或正文中的 `{{NAME}}`、`{{CONTENT}}` 等命名标记，由构建器替换为转义后的值或生成内容。
- 渐进增强（Progressive enhancement）：先保证静态 HTML 可用，再由 `site.js` 添加日期更新和剪贴板反馈等浏览器能力。
- Open Graph：布局输出的 `og:*` 社交分享元数据，用于为页面提供标题、描述、URL 和固定预览图。
- canonical URL：页面的规范链接，帮助搜索引擎将每个生成页面关联到配置中的公开站点地址。
- Workflow：把商品信息、趋势、模型和筛选步骤串起来的可复用业务流程，在仓库中以案例说明和截图呈现。
- RPA：Robotic Process Automation，站点案例中用于承接固定、重复操作的自动化方式。
- `dist/`：`node build.mjs --deploy` 生成的部署目录，只包含页面、样式、脚本和 `assets/`。
- GitHub Pages：工作流将 `dist/` 上传并部署到的静态托管环境。
- Jekyll exclude：`_config.yml` 的排除列表，用于根目录 Pages 兼容发布时隐藏模板、构建脚本和配置源文件。
